Level 1 · Orientation

The big picture

This contribution creates a small, reproducible scientific experiment without changing the team’s shared main branch directly. It asks one preliminary question:

Can Predictive Coding and Backpropagation both run successfully through the same controlled MNIST experiment pipeline?

It does not answer whether Predictive Coding learns better online or forgets less. Instead, it establishes the experimental foundation required before such a comparison can be trusted.

Level 3 · System

What an experiment harness does

A harness is the infrastructure surrounding an experiment. It turns an idea into a repeatable procedure.

Configuration

Fixes model size, learning rates, sample counts, and inference steps.

Data path

Selects balanced examples and freezes their realized order.

Training

Runs PC and BP through a shared interface and loss.

Evaluation

Measures accuracy on a separate deterministic test subset.

Provenance

Records versions, commits, device, seed, and platform.

Evidence safety

Validates records and refuses to overwrite earlier runs.

Scientific boundary

Why this is called “Step 1”

The record is deliberately labeled static-feasibility-only. Static MNIST is one fixed digit-classification problem; there is no sequence of changing tasks or distributions.

Established here

The dependency loads, both methods train, the shared path works, and a reproducible record can be created.

Not established here

Online learning, forgetting, robustness to shift, biological superiority, or PC outperforming BP.

Interpretation limit: a successful smoke record is engineering and method-feasibility evidence—not a comparative scientific result.

Learning paths

How PC and BP differ

Backpropagation

Forward prediction → output error → backward gradient → weight update.

Predictive Coding

Initial prediction → repeated latent-state energy reduction → weight update.

Both methods use the same linear architecture, ReLU activations, one-hot squared-error loss, and Adam parameter optimizer at learning rate 0.001. PC additionally uses latent-state SGD at 0.01.

Compute caveat: PC performs five internal inference iterations per batch. Runtime is recorded, but this smoke test is not a compute-matched performance comparison.

Comparison integrity

How fairness is enforced

A shared nominal seed is not enough. The harness explicitly matches and verifies the consequential parts of the experiment.

Same initialization

The seed resets before each model is built, then all trainable parameters are hashed.

Same examples

The subset is deterministic and class-balanced: 100 training examples per digit.

Same realized order

The order is constructed once and DataLoader shuffling is disabled.

Same evaluation

Both methods use the same separate test identities and metric implementation.

The record validator rejects completed method runs if their stream identities or initial-parameter hashes differ. This turns fairness from an intention into a checked invariant.

Why records cannot be overwritten

Replacing an old result under the same filename can hide failures and destroy traceability. The runner therefore refuses an existing destination. Repetitions must use a fresh output directory.

Verification

What the six protocol tests establish

  1. Configuration inspection works without training or loading MNIST.
  2. The protocol is labeled static and claim-limited.
  3. Stratified sample selection is deterministic and balanced.
  4. PC and BP begin with matching trainable parameters.
  5. Existing evidence cannot be overwritten.
  6. Record validation rejects mismatched realized streams.

These checks validate the experiment’s structural guarantees. They do not establish scientific generalization or method superiority.

The smoke environment is deliberately CPU-only. GPU execution is not silently enabled because CUDA versions, kernels, and hardware can materially affect reproducibility and resource comparisons.

Provenance and licensing

Why Predictive Coding remains a submodule

The team harness calls an external Predictive Coding implementation pinned at commit 5bf803c. The upstream source is not copied into the team-owned runner.

Stable identity

The exact upstream commit is recorded and shared.

Clear boundary

Team orchestration stays separate from externally sourced algorithm code.

Licensing caution

No redistribution permission is inferred while the upstream repository lacks a clear license.

Hands on

Manual setup, testing, and execution

1. Reconstruct the environment

git submodule update --init --recursive
uv sync --locked --extra cpu

2. Inspect the protocol without training

uv run --extra cpu python \
  playground/step1-static-mnist/experiment.py --print-config

3. Run the protocol tests

uv run --extra cpu python -m unittest \
  playground/step1-static-mnist/test_protocol.py

4. Create a fresh smoke artifact

uv run --extra cpu python \
  playground/step1-static-mnist/experiment.py \
  --config smoke \
  --device cpu \
  --methods pc bp \
  --seeds 0 \
  --output-dir /tmp/spuler-step1-test

5. Inspect and validate the repository

python3 -m json.tool /tmp/spuler-step1-test/smoke-seed-0.json
python3 scripts/validate_repository.py
git diff --check
git status --short
What should I confirm in the JSON?
  • Top-level and method statuses are completed.
  • PC and BP have identical initial_parameters_sha256.
  • PC and BP have identical stream_identity.
  • The protocol is step1-static-mnist-v0.1.
  • The interpretation is static-feasibility-only.

Where the project goes next

The feature branch is ready for a pull request into main. After review and merge, the team can build the causal continual-learning BP baseline on the same principles: deterministic realized streams, shared evaluation, preserved evidence, and explicit protocol identity.
